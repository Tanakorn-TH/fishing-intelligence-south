# ระบบดีไซน์ — คลื่นดี

เอกสารนี้บันทึกว่าเรายืมอะไรจาก **ite-avm** มาบ้าง ไม่ยืมอะไร และเพราะอะไร

ite-avm (`github.com/TH-Home/ite-avm`) เป็นโปรเจคของเจ้าของคนเดียวกัน ระบบดีไซน์ของมัน
ถูกล็อกไว้แล้วตาม `SKILL.md` ข้อ 6 — *"ล็อกขั้นสุดท้าย 15 ก.ค. 2569 (ผู้ใช้อนุมัติ
ถูกใจที่สุด ทั้ง Dark/Light)"* มีโทเคน 113 ตัวครบสองโหมด พร้อมเหตุผลกำกับรายบรรทัด

**สถานะ:** ทำแล้ว §4 (ฟอนต์) · §7.1 (safe-area + โทเคนเลย์เอาต์) · §7.2 (ตัวดักใน CI) · §7.4 (พื้นที่กด)
ที่เหลือยังเป็นข้อตกลงที่ยังไม่ลงมือ

## 1. ข้อขัดแย้งเชิงหลักการ — ต้องตัดสินก่อนอย่างอื่น

ite-avm มีกฎเหล็กข้อหนึ่งว่า:

> **มีเงา = ไม่มีขอบ · มีขอบ = ไม่มีเงา (ห้ามใส่ทั้งคู่)**

แต่ `design.css` ของเราสร้างบนนิยาม glassmorphism ซึ่งระบุสัญญาณสี่อย่างที่ต้องมีครบ
**ขาดข้อใดข้อหนึ่งแล้วไม่ใช่ glassmorphism** — และในสี่ข้อนั้นมีทั้ง

- ข้อ 3 ขอบคม 1px ขาวโปร่ง สว่างกว่าที่ขอบบน
- ข้อ 4 ลอยเป็นชั้น เงาฟุ้งกว้าง

**สองระบบนี้เข้ากันไม่ได้โดยนิยาม** ไม่ใช่รายละเอียดที่ปรับจูนได้

### คำตัดสิน: กระจกชนะในเว็บนี้

เหตุผล ไม่ใช่รสนิยม:

1. **ite-avm เองก็ไม่ได้ใช้กฎนี้กับกระจก** — คลาส `.glass` `.deskglass` `.tabglass`
   ของเขาก็มีทั้งขอบไล่แสงและเงาพร้อมกัน กฎ "เงาหรือขอบ" ใช้กับ **การ์ดทึบ** เท่านั้น
   สิ่งที่เราขัดจริง ๆ จึงไม่ใช่กฎ แต่เป็นการที่เว็บเราใช้กระจกเป็นวัสดุหลัก
   ส่วนเขาใช้กับเปลือกแอปอย่างเดียว

2. **เว็บนี้ใช้กลางแดดบนเรือ** พื้นหลัง aurora กับแผ่นกระจกทำให้แยกชั้นได้โดยไม่ต้อง
   พึ่งความต่างของความสว่างมาก ซึ่งเป็นสิ่งที่หายไปเมื่อจอโดนแดด

**ผลที่ตามมา:** ที่ไหนเป็นการ์ดทึบ (ไม่ใช่กระจก) ให้ใช้กฎ ite-avm เต็มที่ —
เงาหรือขอบ อย่างใดอย่างหนึ่ง

### ข้อยกเว้นที่บันทึกไว้แล้ว

| สิ่งของ | ขัดกฎข้อไหน | เหตุผล |
|---|---|---|
| `.glass` `.glass-lite` `.glass-raised` | เงา + ขอบ | เป็นนิยามของวัสดุ ดูข้างบน |
| `.liquid-btn` | เงา + ขอบ · เงา opacity .45 (เพดาน .12) | ผู้ใช้เลือกปุ่มนี้เอง จาก uiverse (MIT) เป็นข้อยกเว้นที่ตั้งใจ ไม่ใช่ของหลุด |
| แผนที่ `.spot-map` | พื้นสว่างในแอปธีมมืด | ตั้งใจให้อ่านเป็น "แผ่นชาร์ต" และอ่านง่ายกลางแดด ค่าสีผ่าน contrast audit บนพื้นครีมมาแล้ว |

ite-avm เองก็มีข้อยกเว้นแบบนี้สองจุด (สีห้องประชุม 16 สี และวงแหวนปฏิทิน) —
การมีข้อยกเว้นที่เขียนไว้ชัดไม่ใช่การแหกกฎ แต่การมีข้อยกเว้นที่ไม่มีใครรู้ต่างหากที่เป็น

## 2. สี — ยกหลักการมา ไม่ยกค่ามา

กฎข้อแรกสุดของ ite-avm:

> **neutral ต้องเอียงไปทางเดียวกับ accent เสมอ** — Claude ใช้พื้นอุ่นเพราะ accent
> เป็นส้มอิฐ (อุ่นคู่อุ่น) แต่ accent เราเป็นฟ้า ซึ่งอยู่ตรงข้ามเหลืองเกือบ 180°
> จึงต้องใช้เทาเย็น

**การคัดลอกค่า `#0d0f13` มาตรง ๆ จะละเมิดกฎนี้** เพราะ accent ของเราคือ aqua `#40ded2`
(เขียวอมฟ้า ~175°) พื้นจึงต้องเอียงไปทางนั้น ซึ่ง `#061a27` ที่ใช้อยู่ทำถูกแล้ว

พาเลตต์ของเราคงเดิมทั้งชุด และแต่ละสีผูกกับความหมายในระบบไปแล้ว:

| โทเคน | ค่า | ความหมายที่ผูกไว้ |
|---|---|---|
| `--aqua` | `#40ded2` | น้ำ · ค่าปัจจุบัน · ตัวชี้ที่กำลังทำงาน |
| `--lime` | `#c8eb69` | คะแนนระดับดีที่สุด · ปุ่มลงมือ |
| `--orange` | `#ffb957` | **ข้อมูลตัวอย่าง ห้ามเชื่อ** — จองไว้เรื่องเดียว |
| `--bg` | `#061a27` | พื้นทะเลลึก |

### กฎการใช้สีที่ยกมาทั้งข้อ

1. **สีเน้นใช้เป็นเส้นขอบ ไม่ถมพื้น** — ห้ามถมพื้นทึบตัวหนังสือขาว (อ่านเป็นคำเตือน)
2. **พื้นของสิ่งที่เน้น ต่างจากพื้นรอบข้างเพียงเล็กน้อย** — แยกชั้นด้วยพื้นและขอบ
   ไม่ใช่ด้วยสีจัด
3. **สีบอกสถานะสงวนไว้บอกสถานะเท่านั้น** ห้ามใช้กับปุ่มหรือป้ายจำนวน
4. **ห้ามเพิ่มสีใหม่เข้าพาเลตต์** — ต้องการเฉดอ่อนให้ใช้ `color-mix()` จากตัวแปรเดิม
5. **ห้ามใช้สีอย่างเดียวสื่อความหมาย** ต้องมีข้อความหรือรูปทรงกำกับเสมอ

ข้อ 3 มีผลจริงกับเว็บนี้: `.datum-badge` (อ้างอิง MSL) **จงใจไม่ใช้ส้ม** ทั้งที่เป็น
คำเตือนเหมือนกัน เพราะถ้าใช้ สัญญาณ "ข้อมูลตัวอย่าง" จะเจือจางจนคนเลิกสังเกต

## 3. หนี้ที่ค้างอยู่ — สีดิบ 150 จุด ✅ ปิดแล้ว (v0.9.8)

`styles.css` ถูก minify เหลือสองบรรทัดและ **hard-code สีไว้ราว 149 จุด ต่อการเรียก
`var()` แค่ 49 ครั้ง** หนักที่สุดคือเฉดตัวอักษรรอง ~50 เฉดที่ต่างกันนิดเดียวและ
ไม่มีตัวแปรรองรับสักตัว (`#9bb7bd` `#83a9af` `#77969e` `#6b9299` …)

**ผลที่ต้องรู้:** ถ้าประกาศทับตัวแปรที่ `:root` จะได้แค่ 49 จุดที่เปลี่ยนตาม
อีกร้อยจุดคาเป็นสีเดิม — **การเปลี่ยนธีมทั้งเว็บทำไม่ได้จนกว่าจะยุบสีพวกนี้เป็นตัวแปรก่อน**

งานนี้ควรทำก่อนคิดเรื่องโหมดสว่าง ไม่ใช่หลัง

โทเคนที่ประกาศแล้วไม่มีใครใช้ ลบได้: `--panel2` (0 การอ้างอิง)

**ผลหลังทำจริง (v0.9.8):** ยุบสีดิบ 139 จุดเป็นตัวแปร เหลือ 0 จุดนอก `:root`
ตัวแปรทั้งหมด 143 ตัว แบ่งเป็น `--ink-*` 74 · `--surface-*` 41 · `--line-*` 11 · `--shadow-*` 8
บวกโทเคนเดิม 9 ตัว · ลบ `--panel2` ออกแล้ว ส่วน `--nav` **ไม่ได้ลบ** เพราะ `design.css`
ใช้เป็นสีตัวอักษรบนปุ่ม `.gear-submit` (เอกสารเดิมนับเฉพาะใน `styles.css` จึงเห็นเป็น 0)

**ไม่ได้รวมเฉดที่ใกล้กัน** — ค่าทุกจุดเท่าเดิมเป๊ะ ยืนยันด้วยการเทียบสีที่คำนวณได้จริง
37,128 ค่า จาก 2,589 อิลิเมนต์ × 3 ช่วงจอ ต่างกัน 0 ค่า
การรวมเฉดคือการเปลี่ยนสี ซึ่งเป็นคนละงานและต้องให้เจ้าของตัดสิน — ดูรายการข้างล่าง

**เฉดที่ใกล้กันจนแทบแยกไม่ออก 18 กลุ่ม รวม 54 ตัวแปร** เช่น
`#7e9fa6 #829fa5 #7fa1aa #81a1a8 #83a2a7 #83a2a8 #83a4aa` ต่างกันไม่เกิน 6 หน่วยต่อช่อง
ถ้ายุบกลุ่มพวกนี้จะเหลือตัวแปรราว 90 ตัว ทำให้ทำโหมดสว่างง่ายขึ้นมาก
แต่ต้องยอมรับว่า **สีจะเปลี่ยนจริง** จึงยังไม่ทำ

## 4. ฟอนต์ ✅ ทำแล้ว

ยกโครงจาก ite-avm มาทั้งหมด

| ชั้น | ฟอนต์ | ใช้กับ |
|---|---|---|
| `--font-sans` | `'Jost Num', 'Noto Sans Thai', …` | ทุกอย่าง |
| `--font-mono` | `'Jost Num', 'JetBrains Mono', 'Noto Sans Thai', …` | รหัส ป้ายกำกับ ตัวเลขในตาราง |
| `--font-num` | `'Jost', 'Noto Sans Thai', …` | (ประกาศไว้ ยังไม่มีใครเรียก) |

### เทคนิค `Jost Num` — ตัวเลขทั้งเว็บเป็นฟอนต์เดียวโดยไม่ต้องติดคลาส

ไฟล์เดียวกับ `Jost` ต่างกันแค่ `unicode-range: U+0030-0039` แล้ววางไว้**หน้าสุด**ของ
ทุก stack เบราว์เซอร์เลือกฟอนต์รายตัวอักษร เลข 0-9 จึงมาจาก Jost ส่วนไทยกับละติน
ตกไปฟอนต์ถัดไป ได้ทั้งสองอย่างในสแปนเดียวกัน

ทำแบบนี้เพราะตัวเลขส่วนใหญ่ในเว็บ *ไม่มีคลาสอะไรเลย* การไล่ติดคลาสทีละจุดไม่มีวันครบ
และโค้ดใหม่จะหลุดอีก — ย้ายมาคุมที่ระดับฟอนต์แทน ถูกอัตโนมัติ

⚠️ ของเราเป็น **static font** จึงต้องประกาศ `Jost Num` แยกทุกน้ำหนัก ห้ามรวบเป็น
`font-weight: 100 900` ชี้ไฟล์เดียวแบบ ite-avm (ของเขาเป็น variable font)
ถ้ารวบ เบราว์เซอร์จะปลอมความหนาให้ เลขหนาจะดูเลอะกว่าตัวอักษรข้าง ๆ ที่หนาจริง

### ที่เปลี่ยนไปแล้ว (v0.9.4)

- **DM Mono → JetBrains Mono** ให้ตรงกับ ite-avm · variable 400–700 ไฟล์เดียว
  31 KB แทน 49 KB ของสี่ไฟล์เดิม · ศูนย์มีจุดกลางวง กัน 0/O สลับตอนอ่านพิกัด
- **เติม `'Noto Sans Thai'` ใน `--font-mono`** — JetBrains Mono ไม่มีสระและวรรณยุกต์ไทย
  สแปนที่ปนไทยกับตัวเลขอย่าง "3.2 ม." ต้องมีที่ให้ตัวไทยตกลงไป
  ite-avm ทำอยู่แล้ว ของเดิมเราตกหล่นข้อนี้

### ที่ตั้งใจต่างจาก ite-avm

`'Jost Num'` ยังอยู่หน้าสุดของ `--font-mono` — ite-avm จงใจไม่ใส่ เพราะฝั่งเขา
`--font-mono` ใช้กับ *รหัสที่อ่านทีละตัว* แต่ 20 selector ที่ใช้ตัวนี้ในเว็บเราเป็น
**จำนวน** แทบทั้งหมด (ความสูงน้ำ ความเร็วลม เวลา คะแนน) ซึ่งกฎของ ite-avm เองบอกให้ใช้
Jost เพราะ *"JetBrains Mono พอขยายเป็นเลข 48px แล้วดูแข็งและเชย"*

### กฎตัวอักษรไทยที่ต้องรักษา

- **line-height ห้ามต่ำกว่า 1.28** — ไทยซ้อนสระบนกับวรรณยุกต์ได้ถึงสามชั้น
- **`letter-spacing: 0` สำหรับ `:lang(th)`** — บีบแล้วสระลอยหลุด
- **ห้าม `font-size` ต่ำกว่า 12px**
- **`.rise` เลื่อนอย่างเดียว ไม่ scale** — scale ทำให้ตัวอักษรไทยเบลอตอนวิ่ง
- **ห้าม `word-break: break-all`** — ตัดกลางพยางค์อ่านไม่ออก ใช้ `line-break: auto`

## 5. ปุ่ม ✅ วางระบบแล้ว (v0.9.9) — ย้ายเข้าระบบ 13 จาก 26 คลาส

ite-avm มี **3 variant เท่านั้น** ไม่มี danger แยก

| ระดับ | หน้าตา | ใช้ตอนไหน |
|---|---|---|
| primary / accent | พื้นไล่เฉด tonal + ตัวอักษรสีเน้นเข้ม weight 600 + เงา | ปุ่มเดียวต่อหน้าจอที่อยากให้กด |
| ghost | พื้น surface + ขอบไล่แสง + ตัวอักษรเทาเข้ม | action รอง |
| text | โปร่งใส ไม่มีขอบ | ยกเลิก · รองที่สุด |

**ค่าที่ยกมาได้ทันที** — pill `border-radius: 9999px` · `padding: .625rem 1.25rem` ·
`font-size: 14px` · `gap: .5rem` (ไอคอนอยู่ซ้ายเสมอ) · `disabled { opacity: .55 }`

### ปุ่ม tonal — ไล่เฉดแทนการถมสีทึบ

```css
background: linear-gradient(180deg, var(--btn-tonal-top), var(--btn-tonal-bot));
color: var(--btn-tonal-ink);
font-weight: 600;
```

นี่คือคำตอบของกฎ "ห้ามถมพื้นทึบตัวหนังสือขาว" — ได้ปุ่มที่เด่นโดยไม่โหดร้าย
hover ปรับด้วย `filter: saturate(1.12) brightness(.985)` **ไม่เปลี่ยนค่าสี**

### จุดที่ต้องแก้ตอนยกมา

⚠️ **ite-avm ลืมใส่พื้นที่กดขั้นต่ำ** — คอมเมนต์ใน `app.css` เขียนว่า "ยกพื้นที่กดให้ถึง
~44px" แต่ในบล็อกนั้นมีแค่ `-webkit-tap-highlight-color` ไม่มี `min-height` เลย
ผลจริง: ปุ่มมาตรฐาน ~41.7px และปุ่มไอคอน 36px ซึ่ง**ต่ำกว่า WCAG 2.5.8**

เว็บเราต้องเติมให้จบ เพราะผู้ใช้อยู่บนเรือ มือเปียก เรือโคลง:

```css
@media (pointer: coarse) { .btn, .icon-btn { min-block-size: 44px; min-inline-size: 44px; } }
```

⚠️ **`translate:` ต้องแยกจาก `transform:`** — Tailwind v4 คอมไพล์ `-translate-y-px`
เป็น property `translate:` จึงไม่ชนกับ `transform: scale(.95)` ตอนกด
ถ้าเขียน CSS เองแล้วใช้ `transform` ทั้งคู่ hover จะลบ active ทิ้ง

## 6. เมนูลอยและชั้นซ้อน — เว็บเราทำถูกกว่าอยู่แล้ว

ผลสำรวจกลับทิศจากที่คาด **ite-avm ไม่มี focus trap เลยสักที่ ไม่คืนโฟกัสกลับปุ่ม
เลยสักที่** และมีบันได z-index `30/35/40/45/50/60` ที่เปราะ พร้อมกับดักที่บันทึกไว้ว่า
`backdrop-filter` สร้าง stacking context จนเมนูมุดใต้การ์ดใบถัดไป ต้องแก้ด้วย
`createPortal` ออกไป `body`

**เว็บเราใช้ `<dialog>` อยู่แล้ว ซึ่งได้ทั้งหมดนั้นฟรี** — focus trap · คืนโฟกัส ·
Escape · ล็อกสกรอลล์ · top layer ที่ไม่สนใจ z-index และไม่ติด stacking context

จึง **ไม่ยกโครงเมนูของ ite-avm มา** สิ่งที่ยกมามีสองอย่าง:

### 6.1 `useKeyboardInset` — ของที่มีค่าที่สุดในชุดนี้

เป็น JS ล้วน ไม่พึ่ง React ยกมาได้ทั้งดุ้น:

```js
kb      = window.innerHeight - vv.height - vv.offsetTop   // แป้นพิมพ์บังเท่าไร
visualH = vv.height
bottom  = vv.height + vv.offsetTop                        // เส้นบนของแป้นพิมพ์
```

แก้ปัญหาที่ iOS **ไม่ย่อ layout viewport** ตอนแป้นพิมพ์ขึ้น ทำให้ `position: fixed;
bottom: 0` ยึดก้นจอจริงใต้แป้นพิมพ์ — กล่องที่ลอยก้นจอจึงมุดหายไปใต้คีย์บอร์ด

### 6.2 ค่าจังหวะแอนิเมชัน

| ท่า | ค่า |
|---|---|
| dropdown เข้า | `opacity 0→1` + `translateY(-6px)→0` · **160ms** ease-out |
| bottom sheet | `translateY(100%)→0` · **200–220ms** ease-out |
| ฉากหลัง | `opacity 0→1` · **150ms** |
| แผงกางจากมุม | `scale .86→1` · **170ms** `cubic-bezier(.2,.9,.3,1.05)` |

**ย่อจาก .86 ไม่ใช่ 0** — ย่อจากศูนย์จะเห็นเป็นจุดเล็กแล้วพองออก ดูเป็นการ์ตูน
ที่ .86 ให้ความรู้สึกว่า "ของอยู่ตรงนั้นแล้ว แค่กางออก"

⚠️ ite-avm **ไม่มีแอนิเมชันออกเลยสักตัว** (ข้อจำกัดของ `{open && <div/>}` ใน React)
เว็บเราทำได้ด้วย `@starting-style` + `transition-behavior: allow-discrete`

## 7. การแสดงผลข้ามอุปกรณ์

ปัจจุบันเราใช้ media query สามจุด: 1050px · 780px · 400px

### 7.1 ยกมาทันที — คุ้มที่สุดต่อบรรทัด ✅ ทำแล้ว (v0.9.5)

**safe-area ต้องหารด้วยตัวคูณซูมก่อน**

```css
:root {
  --sa-l: calc(env(safe-area-inset-left)   / var(--ui-scale));
  --sa-r: calc(env(safe-area-inset-right)  / var(--ui-scale));
  --sa-b: calc(env(safe-area-inset-bottom) / var(--ui-scale));
  --sa-t: calc(env(safe-area-inset-top)    / var(--ui-scale));
}
```

`env()` คืนพิกเซลจริงของจอ แต่ทุกอย่างใต้ `<html>` โดนซูมคูณอีกที ถ้าใช้ตรง ๆ
ระยะกันติ่งกล้องจะเพี้ยนตามระดับซูม หารไว้ก่อน พอโดนคูณกลับจึงได้ระยะจริงเท่าเดิม

หลักการเดียวกันใช้กับทุกที่ที่อ้าง `100vw`

**โทเคนเลย์เอาต์แทนตัวเลขกระจาย** — `--topbar` `--tabbar` `--rail` ทุกที่ที่มีของลอย
อ้าง `calc(var(--tabbar) + var(--sa-b))` แก้ที่เดียวไม่ต้องไล่ห้าจุด

### 7.2 ⚠️ บั๊ก Safari ที่ต้องเช็คในเว็บเราด้วย ✅ ตรวจแล้ว (v0.9.5)

**ห้ามเขียน** `@media (width < 40rem) and (orientation: portrait)` — คอมไพเลอร์แปลงเป็น
Media Queries Level 4 ซึ่ง **Safari ก่อน 16.4 ทิ้งทั้งบล็อกเงียบ ๆ**

ite-avm เจอของจริงบน PWA ของ iPhone: แถบล่างไม่ย้ายลงก้นจอ + ระยะกันท้ายหน้าค้างที่ 0
= ปุ่มหน้าถัดไปกดไม่ถึง ต้องเขียนซ้อนสองชั้น:

```css
@media not all and (min-width: 40rem) {
  @media (orientation: portrait) { … }
}
```

### 7.3 `useNavMode` — ยังไม่ทำ และอาจไม่ต้องทำ

ite-avm ไม่ใช้จุดตัดความกว้างตายตัว แต่ **วัดของจริงบนแถบนำทาง** แล้วเขียน
`<html data-nav="desktop|tablet">` เพราะเมนูถูกตัดตามสิทธิ์แต่ละคน (3–7 รายการ)
ชื่อเมนูไทยยาวไม่เท่ากัน และผู้ใช้ย่อ/ขยายตัวอักษรเองได้

**เว็บเราเมนูเป็นชุดคงที่ 8 รายการเท่ากันทุกคน** — เงื่อนไขที่ทำให้เทคนิคนี้จำเป็น
ไม่มีอยู่ จุดตัดตายตัวเพียงพอ **อย่าเพิ่มความซับซ้อนนี้จนกว่าจะมีระบบผู้ใช้จริง**

### 7.4 พื้นที่กดบนเรือ ✅ ทำแล้ว + มีตัวตรวจใน CI (v0.9.7)

ตรวจด้วย `pointer: coarse` **ไม่ใช่ความกว้างจอ** เพราะแท็บเล็ตจอใหญ่ก็ใช้นิ้ว
ขยายพื้นที่กดด้วย `min-height: 44px` + `margin: -8px 0` โดยไม่เปลี่ยนขนาดที่มองเห็น
เพื่อไม่ให้การ์ดยืดจนเสียสัดส่วน
