# สัญญาของ API

เอกสารนี้เป็นข้อตกลงกลางระหว่างฝั่ง backend กับ frontend
ทุกคนเขียนตามนี้ จึงทำงานขนานกันได้โดยไม่ต้องรอกัน **ห้ามเปลี่ยนรูปแบบโดยไม่แก้เอกสารนี้ก่อน**

## กติการ่วม

- ทุก endpoint เป็น `GET` และคืน `Content-Type: application/json; charset=utf-8`
- สำเร็จ → `{"data": …, "meta": {…}}` · ผิดพลาด → `{"error": {"code": "...", "message": "..."}}`
- `message` เป็นภาษาไทย เขียนให้ผู้ใช้อ่านรู้เรื่อง ห้ามใส่ path ชื่อฐานข้อมูล หรือข้อความ exception ดิบ
- รหัสสถานะ: `400` ค่าที่ส่งมาไม่ถูกต้อง · `502` แหล่งข้อมูลภายนอกล้ม · `503` ระบบเราเองมีปัญหา
- ใช้โครงเดิมที่มีอยู่แล้วเสมอ: `api/lib/http.php` (`fis_json` `fis_fail` `fis_require_get` `fis_handle`)
  และ `api/lib/db.php` (`fis_db()`) **ห้ามเขียน helper ซ้ำ**
- **พิกัด**: รับ-ส่งเป็น `lat` และ `lon` แยกกันเสมอ ห้ามใช้คู่อันดับ
  ในฐานข้อมูล MySQL เก็บเป็น `POINT(lat lon)` (ละติจูดก่อน — กลับด้านกับ PostGIS)
  อ่านออกมาด้วย `ST_Latitude()` / `ST_Longitude()` ห้ามใช้ `ST_X` / `ST_Y`
- เวลาในคำตอบใช้ ISO 8601 พร้อม offset `+07:00` เสมอ
- ทุกคำตอบที่มีค่าความลึกต้องแนบ `"notice": "ข้อมูลความลึกใช้เพื่อวางแผนตกปลาเท่านั้น ห้ามใช้เพื่อการเดินเรือ"`

## `meta` ที่ต้องมีทุก endpoint ที่ดึงข้อมูลจากภายนอก

```json
"meta": {
  "source": "ชื่อแหล่งข้อมูล",
  "source_url": "https://…",
  "license": "…",
  "fetched_at": "2026-08-08T14:05:00+07:00",
  "cached": true
}
```

ที่มาของข้อมูลต้องติดไปกับข้อมูลเสมอ ไม่ใช่ซ่อนไว้ในโค้ด — เป็นกติกาเดียวกับตาราง `data_sources`

## `GET /api/weather.php?lat=6.87&lon=101.25`

สภาพอากาศทะเลปัจจุบันและรายชั่วโมง

```json
{
  "data": {
    "current": {
      "observed_at": "2026-08-08T14:00:00+07:00",
      "temperature_c": 32.1,
      "wind_speed_kmh": 8.4,
      "wind_direction_deg": 225,
      "wind_direction_label": "ตะวันตกเฉียงใต้",
      "wave_height_m": 0.6,
      "precipitation_probability_pct": 10,
      "pressure_hpa": 1009.2
    },
    "hourly": [
      { "time": "2026-08-08T15:00:00+07:00", "temperature_c": 32.0,
        "wind_speed_kmh": 9.1, "wave_height_m": 0.6, "weather_code": 1 }
    ]
  },
  "meta": { … }
}
```

- `hourly` คืน 24 ชั่วโมงข้างหน้านับจากชั่วโมงปัจจุบัน
- `wind_direction_label` เป็นภาษาไทย 8 ทิศ
- `wave_height_m` อาจเป็น `null` ถ้าจุดนั้นไม่มีข้อมูลคลื่น ฝั่ง frontend ต้องรองรับ
- แหล่งข้อมูล: Open-Meteo (ใช้ฟรี ไม่ต้องใช้คีย์) — Forecast API และ Marine API
- ต้องมีแคชฝั่งเซิร์ฟเวอร์ อย่างน้อย 15 นาที ไม่ยิงแหล่งข้อมูลทุกครั้งที่มีคนเปิดหน้า

## `GET /api/solunar.php?lat=6.87&lon=101.25&date=2026-08-08`

ข้างขึ้นข้างแรมและช่วงเวลาที่ปลากินตามทฤษฎี Solunar — **คำนวณเอง ไม่เรียกบริการภายนอก**

```json
{
  "data": {
    "date": "2026-08-08",
    "moon": {
      "phase_name_th": "แรม 8 ค่ำ",
      "illumination_pct": 42,
      "age_days": 22.3
    },
    "major_periods": [
      { "start": "2026-08-08T05:30:00+07:00", "end": "2026-08-08T07:00:00+07:00" }
    ],
    "minor_periods": [
      { "start": "2026-08-08T12:10:00+07:00", "end": "2026-08-08T13:00:00+07:00" }
    ],
    "moonrise": "2026-08-08T23:41:00+07:00",
    "moonset": "2026-08-08T11:52:00+07:00"
  },
  "meta": { "source": "คำนวณในระบบ", "method": "…", "fetched_at": "…", "cached": false }
}
```

- Major = ช่วงที่ดวงจันทร์ผ่านเมริเดียน (บน/ล่าง) ยาวช่วงละ 2 ชั่วโมง
- Minor = ช่วงจันทร์ขึ้นและจันทร์ตก ยาวช่วงละ 1 ชั่วโมง
- `phase_name_th` ใช้ระบบข้างขึ้นข้างแรมไทย เช่น "ขึ้น 15 ค่ำ" "แรม 8 ค่ำ"
- ถ้าวันนั้นไม่มีจันทร์ขึ้นหรือจันทร์ตก (เกิดขึ้นได้) ให้คืน `null` อย่าเดาค่า

## `GET /api/tides.php?lat=6.87&lon=101.25&date=2026-08-08`

ระดับน้ำรายชั่วโมงและเวลาที่น้ำขึ้นเต็มที่ / ลงเต็มที่ ของวันนั้น

```json
{
  "data": {
    "date": "2026-08-08",
    "datum": "mean_sea_level",
    "current": {
      "time": "2026-08-08T17:00:00+07:00",
      "height_m": 0.77,
      "trend": "falling"
    },
    "extremes": [
      { "type": "high", "time": "2026-08-08T04:12:00+07:00", "height_m": 0.93 },
      { "type": "low",  "time": "2026-08-08T11:05:00+07:00", "height_m": 0.47 }
    ],
    "series": [
      { "time": "2026-08-08T00:00:00+07:00", "height_m": 0.69 }
    ],
    "notice": "ระดับน้ำอ้างอิงระดับน้ำทะเลปานกลาง (MSL) ไม่ใช่ระดับน้ำลงต่ำสุด (chart datum) ตัวเลขจึงเทียบกับตารางน้ำของกรมอุทกศาสตร์ไม่ได้ ใช้เพื่อดูจังหวะน้ำขึ้นน้ำลงเท่านั้น ห้ามใช้เพื่อการเดินเรือ"
  },
  "meta": { … }
}
```

- `series` คืน 24 จุด จุดละหนึ่งชั่วโมง ตั้งแต่ 00:00 ถึง 23:00 ของวันที่ขอ
- `trend` เป็น `"rising"` หรือ `"falling"` · เป็น `null` ถ้าเทียบไม่ได้
- `current` เป็น `null` ถ้าวันที่ขอไม่ใช่วันนี้ — อย่าเดาว่า "ตอนนี้" ของวันอื่นคือเวลาไหน
- `extremes` เรียงตามเวลา และ `type` ต้องสลับ high/low เสมอ ถ้าไม่สลับแปลว่าตรวจจุดยอดพลาด
- **`datum` ต้องส่งทุกครั้ง และ `notice` ห้ามตัดออก** เหตุผลอยู่ย่อหน้าถัดไป

### เรื่อง datum ที่ห้ามมองข้าม

แหล่งข้อมูลอ้างอิง **ระดับน้ำทะเลปานกลาง (MSL)** แต่ตารางน้ำของกรมอุทกศาสตร์ กองทัพเรือ
อ้างอิง **ระดับน้ำลงต่ำสุด (chart datum)** สองอันนี้ต่างกันประมาณครึ่งหนึ่งของพิสัยน้ำ
ค่าที่ได้จาก endpoint นี้จึงเป็นคนละเลขกับตารางน้ำทางการ **แม้จะเป็นเวลาและสถานที่เดียวกัน**

สิ่งที่ใช้ได้จริงคือ **จังหวะ** (น้ำขึ้นน้ำลงตอนกี่โมง) และ **พิสัย** (วันนี้น้ำเกิดหรือน้ำตาย)
เพราะพิสัยไม่ขึ้นกับ datum ส่วน **ความลึกสัมบูรณ์ห้ามเอาไปใช้** เจ้าของข้อมูลเองระบุว่า
ความแม่นในเขตชายฝั่งมีจำกัดและไม่เหมาะกับการเดินเรือ

### ข้อจำกัดอื่น

- **พยากรณ์ล่วงหน้าได้ 7 วัน** เกินกว่านั้นคืน `400` `date_out_of_range` พร้อมบอกช่วงที่ขอได้
  (ปลายทาง "รับ" ช่วงวันที่ได้ถึง ~15 วันก็จริง แต่แบบจำลองมีค่าจริงราว 8 วัน
  เลยจากนั้นตอบ `200` พร้อมค่า `null` ล้วน — อย่าเชื่อว่าไม่ error แปลว่ามีข้อมูล)
- จุดที่แบบจำลองไม่ครอบคลุม (กลางแผ่นดิน แหล่งน้ำปิด ขั้วโลก) คืน `400` `no_tide_data`
  **ห้ามคืน `502`** เพราะนั่นแปลว่าแหล่งข้อมูลล้ม ซึ่งคนละเรื่องกับ "จุดนี้ไม่มีข้อมูล" และทำให้ไล่ปัญหาผิดทาง
- ความละเอียดของแบบจำลองคือ 0.08° (~8 กม.) หมายที่ห่างกันไม่กี่กิโลเมตรจะได้ค่าชุดเดียวกัน
- ต้นทางให้ค่าเป็นรายชั่วโมง เวลาน้ำขึ้นเต็มที่จึงมาจากการประมาณจุดยอดด้วยพาราโบลา
  คลาดเคลื่อนได้ระดับ **5-15 นาที** ค่าที่คืนจึงปัดเป็น 5 นาที ไม่ใช่รายนาที
- แหล่งข้อมูล: Open-Meteo Marine API (`sea_level_height_msl`) ซึ่งใช้แบบจำลอง MeteoFrance SMOC
- ต้องมีแคชฝั่งเซิร์ฟเวอร์อย่างน้อย 30 นาที (น้ำเปลี่ยนช้ากว่าอากาศ ไม่ต้องดึงถี่เท่า)

## `GET /api/score.php?lat=6.87&lon=101.25&date=2026-08-08`

Fishing Score — คะแนนความน่าออกทะเลของวันนั้น แยกตามประเภทงานตกปลา

**สูตรและน้ำหนักทั้งหมดอยู่ใน [`docs/fishing-score.md`](fishing-score.md) อ่านที่นั่นก่อนแก้โค้ด**
ชุดทดสอบเทียบน้ำหนักในโค้ดกับตารางในเอกสารทุกตัว แก้ที่เดียวแล้วอีกที่ไม่ตามจะตก

```json
{
  "data": {
    "date": "2026-08-08",
    "evaluated_at": "2026-08-08T18:20:00+07:00",
    "evaluated_scope": "now",
    "overall": { "score": 74, "label": "ดี", "from_styles": ["trolling", "float", "lightgame"] },
    "best_style": "trolling",
    "styles": [
      { "key": "trolling", "name_th": "ทรอลลิ่ง", "tagline": "…", "score": 75, "label": "ดี",
        "breakdown": [
          { "factor": "wave_calm", "label": "คลื่นสงบ", "weight": 0.3,
            "value": 0.904, "contribution": 27.1, "note": "คลื่น 0.24 ม." }
        ] }
    ],
    "safety": { "level": "good", "label": "ออกได้", "reasons": [], "basis": "…" },
    "factors": { "wave_calm": { "value": 0.904, "note": "คลื่น 0.24 ม." } },
    "notice": "คะแนนนี้เป็นเครื่องมือช่วยวางแผน ไม่ใช่คำพยากรณ์ว่าจะได้ปลา …"
  },
  "meta": { "formula_version": "1.1", "formula_doc": "docs/fishing-score.md", … }
}
```

- `styles` เรียงจากคะแนนมากไปน้อย · `best_style` คือตัวแรกเสมอ
- `overall` = ค่าเฉลี่ยของ 3 งานที่คะแนนสูงสุด (เหตุผลอยู่ในเอกสารสูตร)
- **`contribution` ของทุกปัจจัยรวมกันต้องเท่ากับ `score` ของงานนั้น** — ถ้าไม่เท่าแปลว่า
  breakdown ที่โชว์ให้ผู้ใช้ดูไม่ใช่ที่มาของคะแนนจริง ซึ่งผิดกติกาข้อสำคัญที่สุดของโปรเจค
- `evaluated_scope` เป็น `now` เมื่อขอวันนี้ และ `midday` เมื่อขอวันอื่น
  (คำว่า "ตอนนี้" ของวันอื่นไม่มีความหมาย จึงประเมินที่เที่ยงวันแทน)
- **`safety` แยกจากคะแนนเสมอ ห้ามยุบรวม** คะแนน 70 กับ "ลมแรงเกินไปสำหรับเรือเล็ก"
  เป็นคนละคำถาม และคำถามหลังสำคัญกว่า frontend ต้องแสดงแยกให้เห็นชัด
- **`notice` ห้ามตัดออก** เพราะคะแนนนี้มาจากน้ำหนักที่เราเลือกเอง ไม่ได้ปรับจากสถิติการจับปลาจริง
- ขอบเขตวันที่และกรณี `no_tide_data` ใช้กติกาเดียวกับ `/api/tides.php` เพราะคะแนนต้องพึ่งข้อมูลน้ำ
- **ลม คลื่น และโอกาสฝน เป็นค่าพยากรณ์ของวันและเวลาที่ประเมิน ไม่ใช่ของ "ตอนนี้"**
  (ก่อนสูตรเวอร์ชัน `1.1` ใช้ค่าปัจจุบันกับทุกวัน ซึ่งทำให้คะแนนของวันข้างหน้าไม่มีความหมาย)
  ส่วน `/api/weather.php` ยังตอบสภาพ ณ ตอนนี้อย่างเดียวตามเดิม ไม่รับพารามิเตอร์ `date`
- ปัจจัย `water_moderate` (เพิ่มในเวอร์ชัน `1.1`) ใช้เฉพาะงานอุปกรณ์เบา คือ `float` และ `lightgame`
  ให้คะแนนสูงสุดที่แรงน้ำช่วงกลาง ต่างจาก `water_movement` ที่ยิ่งแรงยิ่งดี


## `GET /api/outlook.php?lat=6.87&lon=101.25&days=8`

คะแนนรวมของหลายวันติดกัน สำหรับปฏิทินวางแผนทริป
ใช้สูตรและน้ำหนักชุดเดียวกับ `/api/score.php` (ทั้งคู่เรียก `api/lib/scoring.php`)

```json
{
  "data": {
    "from": "2026-08-08",
    "to": "2026-08-15",
    "days": [
      { "date": "2026-08-08", "score": 79, "label": "ดี",
        "best_style": "trolling", "best_style_name": "ทรอลลิ่ง", "safety": "good" },
      { "date": "2026-08-16", "score": null, "label": null,
        "reason": "ไม่มีข้อมูลระดับน้ำของวันนี้" }
    ],
    "best_day": "2026-08-13",
    "notice": "…"
  },
  "meta": { "max_days": 8, "horizon_note": "…" }
}
```

- **ขอได้ไม่เกิน 8 วัน** เพราะคะแนนต้องใช้ข้อมูลระดับน้ำ ซึ่งพยากรณ์ได้ราว 7 วัน
- วันที่คิดคะแนนไม่ได้คืน `score: null` พร้อม `reason` — **ห้ามเติมตัวเลขให้เต็มเดือน**
  ปฏิทินต้องแสดงว่า "ยังไม่รู้" ตรง ๆ เพราะคนเอาไปเลือกวันออกทะเลจริง
- ทุกวันประเมินที่เที่ยงวันเหมือนกันหมด เพื่อให้เทียบกันได้บนฐานเดียวกัน
- `safety` ติดมาด้วยทุกวัน เพราะปฏิทินคือที่ที่คนเลือกวันออกเรือ
  เห็นคะแนนสูงแล้วจองวันโดยไม่รู้ว่าลมแรงคือความผิดพลาดที่แพง

## `GET /api/spots.php` (มีอยู่แล้ว)

ไม่เปลี่ยนรูปแบบ · ตารางจะว่างจนกว่าจะมีคนรัน `db/seed-fishing-spots.sql`
จึงอาจคืน `{"data": [], "count": 0}` — ฝั่ง frontend ต้องแสดงสถานะว่างให้ถูกต้อง ไม่ใช่หน้าพัง

หมุดบนแผนที่ **ไม่ได้** มาจาก endpoint นี้ แต่มาจากไฟล์สแตติกใน `map/`
เพื่อให้แผนที่ทำงานได้แม้ฐานข้อมูลยังว่าง (ดูตารางไฟล์ข้อมูลแผนที่ท้ายเอกสาร)

| พิกัดหมายที่ผู้ใช้เพิ่มเอง | ยังไม่มีระบบผู้ใช้ จึงยังเพิ่มหมายเองไม่ได้ |

## ไฟล์ข้อมูลแผนที่ (สแตติก ไม่ใช่ endpoint)

หน้าเว็บโหลดตรงจาก `map/` ไม่ผ่าน PHP เพราะเป็นข้อมูลที่ไม่เปลี่ยนระหว่างวัน
ทุกไฟล์มีบล็อก `metadata` บอกที่มาและสัญญาอนุญาตติดอยู่ในตัวไฟล์เอง

| ไฟล์ | เนื้อหา | ที่มา | สร้างด้วย |
|---|---|---|---|
| `map/coastline-south.json` | เส้นชายฝั่ง | Natural Earth 1:10m (public domain) | `scripts/build-coastline.mjs` |
| `map/borders-south.json` | เขตแดนประเทศและเขตจังหวัด | Natural Earth 1:10m (public domain) | `scripts/build-borders.mjs` |
| `map/depth-south.json` | เส้นความลึกโดยประมาณ | NOAA ERDDAP etopo180 (public domain) | `scripts/build-bathymetry.mjs` |
| `map/reefs-south.json` | ปะการังเทียม 107 จุด | กรมประมง ผ่าน data.go.th (Open Data Common) | `scripts/build-spots.py` |
| `map/marks-south.json` | หมาย 12 จุด (ซากเรือ กองหิน แนวปะการังที่มีชื่อ) | OpenStreetMap (ODbL 1.0) | `scripts/build-spots.py` |

- **เขตแดนในไฟล์เป็นเขตบนบกเท่านั้น** Natural Earth ไม่มีเขตแดนทางทะเล
  ห้ามใช้ตัดสินว่าเรืออยู่ในน่านน้ำประเทศใด
- จังหวัดของหมายใน `marks-south.json` คือ **จังหวัดที่ใกล้ที่สุด** ไม่ใช่เขตปกครองจริง
  เพราะหมายกลางทะเลไม่ได้อยู่ในเขตปกครองของจังหวัดไหน
- `db/seed-fishing-spots.sql` สร้างจากรอบเดียวกับ `marks-south.json`
  ไว้เติมตาราง `fishing_spots` เมื่อมีคนที่เข้าถึงฐานข้อมูลได้รันให้

**ตอนนี้ไม่มีตัวเลขตัวอย่างเหลือในหน้าเว็บแล้ว** ทุกตัวเลขที่ผู้ใช้เห็นมาจากข้อมูลจริง
ถ้าจะเพิ่มอะไรที่ยังไม่มีข้อมูล ต้องกลับมาใส่ป้ายกำกับตามกติกาเดิม

น้ำขึ้นน้ำลงย้ายออกจากตารางนี้แล้ว มี `/api/tides.php` ให้ใช้ แต่**ยังไม่ใช่ข้อมูลระดับตารางน้ำทางการ**
อ่านหัวข้อ "เรื่อง datum ที่ห้ามมองข้าม" ก่อนเอาไปแสดงผล

ตราบใดที่ยังไม่มี ให้ frontend แสดงว่า "ยังไม่มีข้อมูล" ตรง ๆ
**ห้ามแสดงตัวเลขตัวอย่างโดยไม่บอกผู้ใช้ว่าเป็นตัวอย่าง** — คนเอาไปวางแผนออกทะเลจริง
