# การนำขึ้นระบบจริง

ปลายทาง: `https://fishing.yru.ac.th` — Apache 2.4.65 + mod_fcgid + PHP 8.4.11 + MySQL 8.0.46
เซิร์ฟเวอร์อยู่วง `10.10.2.164` · คนนอกเข้าเว็บผ่าน Cloudflare ได้ แต่ **SFTP / FTP / MySQL ต้องอยู่ในเครือข่ายมหาวิทยาลัย**

## ข้อจำกัดของบัญชีบนเซิร์ฟเวอร์

บัญชี `fishing` เป็น **sftp-only** — ล็อกอินด้วยกุญแจ SSH ได้ แต่**รันคำสั่งบนเซิร์ฟเวอร์ไม่ได้**

```
$ ssh fishing@fishing.yru.ac.th "ls"
This service allows sftp connections only.
```

การ deploy จึงเป็นการส่งไฟล์ล้วน ๆ ผ่าน SFTP ไม่มีขั้นตอนที่ต้องสั่งงานฝั่งเซิร์ฟเวอร์
(อย่าเสียเวลาเขียนสคริปต์แบบ `tar | ssh` หรือ `ssh ... "command"` — ใช้ไม่ได้)

โครงสร้างโฟลเดอร์บนเซิร์ฟเวอร์

```
/home/fishing/web/fishing.yru.ac.th/
├── public_html/   ← document root  (index.html, styles.css, app.js, api/)
├── private/       ← อยู่นอก document root  (.env อยู่ตรงนี้)
├── logs/
└── cgi-bin/  document_errors/  stats/
```

## deploy (ใช้ทุกครั้ง)

ต้องอยู่ในเครือข่ายมหาวิทยาลัย แล้ว**ดับเบิลคลิก `deploy.cmd`** ที่รากโปรเจกต์
หรือพิมพ์ `.\deploy.cmd` ใน PowerShell · ใน Git Bash ใช้ `bash ops/deploy.sh`

> PowerShell บนเครื่องนี้หา `bash` ไม่เจอ (หรือไปเจอของ WSL) `deploy.cmd` จึงเรียก Git Bash ให้ตรง ๆ

สคริปต์ทำตามลำดับนี้ และ**หยุดทันทีถ้าขั้นใดล้ม** ก่อนขั้นที่ 6 ยังไม่มีอะไรถูกส่งขึ้นไป

1. **ตรวจการเชื่อมต่อ** — เครื่องใหม่จะถูกเตรียมให้อัตโนมัติ (ดูหัวข้อถัดไป)
2. **ทดสอบในเครื่อง** — `node --check`, ตรวจ id ของ DOM, ตรวจเลขเวอร์ชัน, ตรวจ HTML
3. **ตรวจรายการไฟล์** — ไฟล์ใหม่ที่ลืมใส่รายการจะถูกจับตรงนี้
4. **เทียบกับเว็บจริง**
   - `app.js` / `map.js` / css เปลี่ยน แต่เลขเวอร์ชันเท่ากับบนเว็บ → ถามว่าจะขยับให้ไหม
     (เซิร์ฟเวอร์แคชไฟล์พวกนี้ไว้ 10 ปี ถ้าไม่ขยับ คนที่เคยเข้าเว็บจะไม่เห็นของใหม่เลย)
   - เลขในเครื่องเก่ากว่าบนเว็บ → เตือนว่ากำลังส่งโค้ดเก่าทับ (มักแปลว่าลืม `git pull`)
5. **สรุปก่อนส่ง** — branch, commit, ไฟล์ที่ยังไม่ commit และ main บน GitHub ใหม่กว่าเครื่องนี้ไหม
   ส่งจาก branch ไหนก็ได้ ไม่ต้องรอ merge — แค่ให้เห็นว่ากำลังส่งอะไร แล้วถาม `y/n`
6. **ส่งไฟล์ผ่าน SFTP** แล้ว **เรียก `/api/health.php`** ตรวจว่าตอบ 200

รายการไฟล์ประกาศไว้ตายตัวในสคริปต์ ไม่ได้กวาดทั้งโฟลเดอร์ — `.git`, `.env`, `tests/`, `scripts/`,
`.github/` และไฟล์เอกสารจึงไม่มีทางหลุดขึ้น production

ขยับเวอร์ชันเองก็ได้ ไม่ต้องไล่แก้ 7 จุด

```bash
node scripts/bump-version.mjs
```

(`minor` สำหรับความสามารถใหม่ หรือใส่เลขเอง เช่น `node scripts/bump-version.mjs 1.0.0`)

## เครื่องใหม่ / หลังล้างเครื่อง

ไม่ต้องเตรียมอะไรเอง รัน `deploy.cmd` ได้เลย — `ops/setup-machine.sh` จะทำส่วนที่ขาดให้

| สิ่งที่ต้องมี | อยู่ที่ | ใครทำ |
|---|---|---|
| ค่าเชื่อมต่อ | `~/.fishing-secrets/deploy.env` | สร้างให้อัตโนมัติ ค่าทุกตัวรู้อยู่แล้ว |
| กุญแจ SSH ของเครื่องนี้ | `~/.ssh/fishing_deploy` | สร้างให้อัตโนมัติ |
| กุญแจอยู่ใน `~/.ssh/authorized_keys` บนเซิร์ฟเวอร์ | เซิร์ฟเวอร์ | **ถามรหัส FTP ของบัญชี `fishing` หนึ่งครั้ง** |

ทำไมต้องใช้รหัส FTP: บัญชีนี้เป็น sftp-only ใช้ `ssh-copy-id` ไม่ได้ และรหัส FTP กับรหัส SSH เป็นคนละตัว
สคริปต์จึงส่งกุญแจผ่าน FTPS แล้วตั้งสิทธิ์ด้วย `SITE CHMOD 700 /.ssh` กับ `SITE CHMOD 600 /.ssh/authorized_keys`
(FTP อัปโหลดมาเป็น `664` ซึ่ง sshd ปฏิเสธ · `MFF UNIX.mode` ใช้กับเซิร์ฟเวอร์นี้ไม่ได้)

- รหัส FTP **ไม่ถูกเก็บลงไฟล์ใด ๆ** — พิมพ์ครั้งเดียว ส่งให้ curl ทาง stdin แล้วทิ้ง
- กุญแจของเครื่องอื่นบนเซิร์ฟเวอร์ไม่ถูกลบ สคริปต์อ่านของเดิมมาต่อท้าย
  กุญแจของเครื่องที่ล้างไปแล้วจะค้างอยู่ ลบเองผ่าน FTP ได้ถ้าต้องการ

### ใบรับรอง FTPS

ใบรับรอง FTPS ของเซิร์ฟเวอร์เป็น self-signed ของ Hestia (`CN=host154.yru.ac.th`) ตรวจกับ CA ไม่ได้
สคริปต์จึง**ตรึงกุญแจสาธารณะของใบรับรอง**ไว้ที่ `FTP_PIN` ใน `ops/setup-machine.sh`
แทนการปิดการตรวจเฉย ๆ รหัส FTP จะได้ไม่ถูกส่งให้เครื่องอื่นที่แอบอ้าง

ถ้าสคริปต์ฟ้องว่าใบรับรองไม่ตรง แปลว่าเซิร์ฟเวอร์เปลี่ยนใบรับรอง หรือมีอะไรคั่นกลาง
ถามผู้ดูแลเซิร์ฟเวอร์ให้แน่ใจก่อน แล้วค่อยเอาค่าใหม่จากคำสั่งนี้ไปแทน

```bash
echo QUIT | openssl s_client -starttls ftp -connect fishing.yru.ac.th:21 2>/dev/null | openssl x509 -pubkey -noout | openssl pkey -pubin -outform der | openssl dgst -sha256 -binary | openssl enc -base64
```

## ตั้งค่าเซิร์ฟเวอร์ครั้งแรก (`--setup`)

ใช้ครั้งเดียวตอนตั้งเซิร์ฟเวอร์ใหม่ หรือตอนเปลี่ยนรหัสฐานข้อมูล — deploy ปกติไม่ต้องใช้

```bash
bash ops/deploy.sh --setup
```

`--setup` จะทำเพิ่มจากการส่งโค้ดปกติ 2 อย่าง

- สร้าง `.env` สำหรับเซิร์ฟเวอร์จาก `.env` ในเครื่อง โดย**เปลี่ยน `DB_HOST` เป็น `localhost`**
  (บนเซิร์ฟเวอร์ PHP กับ MySQL อยู่เครื่องเดียวกัน) แล้วส่งไปไว้ที่ `private/` นอก document root
- สร้าง `.htaccess` ใน document root ที่มี `SetEnv FIS_ENV_FILE ...` ชี้ตำแหน่ง `.env` ให้ PHP รู้

## ตรวจหลัง deploy

```bash
curl -s https://fishing.yru.ac.th/api/health.php
```

ควรได้ `"ok":true` และ `"tables_found":8` ตรวจเรื่องความปลอดภัยด้วย — สองอันนี้ต้อง**ไม่ใช่** 200

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://fishing.yru.ac.th/.env
```

```bash
curl -s -o /dev/null -w "%{http_code}\n" https://fishing.yru.ac.th/api/lib/db.php
```

## แก้ปัญหา

| อาการ | สาเหตุ |
|---|---|
| `This service allows sftp connections only` | ปกติ — บัญชีนี้ไม่มี shell ใช้ SFTP เท่านั้น |
| SSH ขอรหัสผ่านทั้งที่ติดตั้งกุญแจแล้ว | สิทธิ์ไฟล์ผิด ต้อง `.ssh` = 700 และ `authorized_keys` = 600 — รัน `deploy.cmd` อีกครั้ง สคริปต์ตั้งสิทธิ์ใหม่ให้ ถ้ายังไม่หาย โฟลเดอร์ home ต้องไม่ให้ group เขียนได้ (ขอผู้ดูแลตั้ง `750`) |
| ติดตั้งกุญแจแล้วขึ้น `รหัส FTP ไม่ถูก` | รหัส FTP กับรหัส SSH เป็นคนละตัว ตั้งรหัส FTP ใหม่ได้ใน Hestia |
| `ใบรับรอง FTPS ... ไม่ตรงกับที่ตรึงไว้` | ดูหัวข้อใบรับรอง FTPS ข้างบน |
| `ขยับเวอร์ชันก่อน` | ไฟล์หน้าเว็บเปลี่ยนแต่เลขเวอร์ชันยังเท่าบนเว็บ รัน `node scripts/bump-version.mjs` |
| health ตอบ 503 `ไม่พบ extension pdo_mysql` | `sudo apt install php8.4-mysql` แล้วรีสตาร์ท Apache |
| health ตอบ 503 `ต่อฐานข้อมูลไม่ได้` | `.env` บนเซิร์ฟเวอร์ผิด หรือ `.htaccess` ไม่ได้ตั้ง `FIS_ENV_FILE` |
| `tables_found` ไม่ครบ 8 | ยังไม่ได้โหลด `data-model.sql` เข้าฐานข้อมูล |
| ต่อ SFTP ไม่ได้เลย | ไม่ได้อยู่ในเครือข่ายมหาวิทยาลัย — ข้างนอกชื่อนี้ชี้ไป Cloudflare ซึ่งไม่เปิด SSH |
